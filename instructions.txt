
# MCP Server Tools - Full Documentation (TXT Version)

This document explains, in detail, every tool exposed by your MCP server:

- list_directory
- get_file_content
- list_files_recursive
- get_file_size

All descriptions follow a strict and explicit structure suitable for prompt engineering, grading, or lab evaluation.

====================================================================
1. TOOL: list_directory
====================================================================

DESCRIPTION:
This tool lists the contents of a SINGLE directory.  
It is NON‑RECURSIVE — it does NOT enter subfolders.

It separates results into:
- directories (only folders)
- files (only regular files)

------------------------------------------------------------
INPUT:
    dir_path : str  
    * Required.  
    The relative path to the directory you want to inspect.

Examples:
    "."                      → the root directory
    "docs"                   → a subfolder
    "src/components"         → nested folder

------------------------------------------------------------
OUTPUT:
A dictionary with two keys:
    {
      "directories": [...],
      "files": [...]
    }

INTERPRETATION GUIDELINES:

1. SUCCESS (directory exists):

    {
      "directories": ["images", "logs"],
      "files": ["readme.txt", "config.json"]
    }

2. EMPTY DIRECTORY:

    {
      "directories": [],
      "files": []
    }

3. ERROR: Access Attempt Outside Sandbox:

    {
      "directories": [],
      "files": ["Access denied."]
    }

4. ERROR: Directory Does Not Exist:

    {
      "directories": [],
      "files": ["Directory does not exist."]
    }

------------------------------------------------------------
IMPORTANT RULES FOR USE:
- Never use this tool to check file content.
- Always use this tool BEFORE accessing a folder with other tools.
- All paths MUST be relative.
- The root directory is ".".


====================================================================
2. TOOL: get_file_content
====================================================================

DESCRIPTION:
Reads and returns the ENTIRE CONTENT of a single file.

This tool does NOT inspect directories.  
It MUST only be used on valid file paths.

------------------------------------------------------------
INPUT:
    file_path : str  
    * Required.  
    The exact relative path to the file.

Examples:
    "readme.txt"
    "docs/manual.md"
    "src/config/settings.json"

------------------------------------------------------------
OUTPUT:
A STRING — always a single string.

INTERPRETATION GUIDELINES:

1. SUCCESS:
    The returned string is the full raw text of the file.

2. ERROR: Access Denied:
    "Access denied."

3. ERROR: File Does Not Exist:
    "Eroare: Fișierul '<name>' nu există."

4. ERROR: The Path Is Not a File:
    "Eroare: '<name>' nu este un fișier valid."

------------------------------------------------------------
IMPORTANT RULES FOR USE:
- Never call this tool on a directory.
- Always verify the file exists using list_directory first.
- Paths must always be relative.


====================================================================
3. TOOL: list_files_recursive
====================================================================

DESCRIPTION:
This tool lists ALL FILES (ONLY FILES) inside a directory AND all its subdirectories.

It performs a full recursive walk of the folder tree.

IMPORTANT:
- It returns FILES ONLY.
- It returns RELATIVE PATHS.
- It returns Unix-style paths `/` even on Windows.

------------------------------------------------------------
INPUT:
    dir_path : str  
    * Required.  
    The directory to recursively scan.

Examples:
    "."                      → scan the entire workspace
    "src"                    → scan src and all subfolders
    "content/articles"       → scan a deep path

------------------------------------------------------------
OUTPUT:
Dictionary with one key:
    {
      "files": [...]
    }

INTERPRETATION GUIDELINES:

1. SUCCESS (files found):

    {
      "files": [
          "main.py",
          "docs/readme.txt",
          "src/utils/helpers.py"
      ]
    }

2. NO FILES FOUND (directory exists but empty):

    {
      "files": []
    }

3. ERROR: Access Outside Sandbox:

    {
      "files": ["Access denied."]
    }

4. ERROR: Directory Does Not Exist:

    {
      "files": ["Directory does not exist."]
    }

====================================================================
4. TOOL: get_file_size
====================================================================

DESCRIPTION:
Returns the SIZE of a file in BYTES.

The tool performs strict sandbox validation and ensures no escape from ADMIN_ROOT.

------------------------------------------------------------
INPUT:
    file_path : str
    * Required.
    A RELATIVE path to a file.

Examples:
    "readme.txt"
    "docs/spec.pdf"
    "project/src/app.py"

------------------------------------------------------------
OUTPUT:
A SINGLE STRING.

SUCCESS:
    "<N> bytes"
Example:
    "2048 bytes"

ERROR – Access denied:
    "Access denied."

ERROR – File does not exist:
    "Error: File '<name>' does not exist."

ERROR – Path is not a file:
    "Error: '<name>' is not a valid file."

====================================================================
5. TOOL: find_largest_file
====================================================================

DESCRIPTION:
This tool recursively searches a given directory and all its subdirectories
to find the largest file. It returns the file path relative to ADMIN_ROOT
and its size in bytes. The tool is sandboxed: it cannot access files outside
ADMIN_ROOT.

------------------------------------------------------------
INPUT:
    dir_path : str  (required)
    - Relative path to the directory to scan.
    Examples:
        "."                 -> scan root folder
        "uploads"           -> scan a subfolder
        "src/data"          -> scan nested folder

------------------------------------------------------------
OUTPUT:
    A single string describing the largest file:
        Largest file: <relative_path> with size: <size> bytes

------------------------------------------------------------
INTERPRETATION GUIDELINES:

1. SUCCESS – largest file found:
    Largest file: docs/manual.pdf with size: 204800 bytes

2. EMPTY DIRECTORY – no files found:
    No files found in the directory.

3. ERROR – access outside sandbox:
    Access denied.

4. ERROR – directory does not exist:
    Error: Directory 'some_folder' does not exist.

------------------------------------------------------------
IMPORTANT RULES FOR USE:
- Tool must only be used on directories.
- All paths must be relative to ADMIN_ROOT.
- The root directory is ".".
- Always verify the folder exists before using the tool.
- This tool recursively scans all subdirectories.

------------------------------------------------------------
NOTE:
- File size is returned in bytes.
- The tool uses recursion exactly as in the provided method.
====================================================================

------------------------------------------------------------
RULES:
- Use list_directory first to check existence.
- NEVER call it on folders.
- NEVER provide absolute paths.
- ALWAYS use relative paths.
- Returned value is ALWAYS "<number> bytes" with no extra text.


------------------------------------------------------------
IMPORTANT RULES FOR USE:
- Use list_directory first to confirm the folder exists.
- This tool DOES NOT return folders.
- Always treat returned paths as valid files.


====================================================================
GENERAL RULES FOR ALL TOOLS
====================================================================
All paths must be RELATIVE  
Absolute paths are forbidden  
Never attempt directory traversal (../) — it will be blocked  
The root directory is "."  
The agent must ALWAYS use tools — never assume filesystem state
